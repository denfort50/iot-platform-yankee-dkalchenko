# Liquibase: структура и именование

## Расположение в resources

Все файлы Liquibase лежат в **одной** директории: `db/changelog/` (дефолт Spring Boot).

```
db/changelog/
├── db.changelog-master.xml   # Корневой changelog, только <include>, без changeset
├── changes/                   # Отдельные changelog-файлы (по одному на миграцию/релиз)
│   ├── changelog-001-init-database.xml
│   └── changelog-002-collector-tables.xml
└── sql/                       # SQL-скрипты, вызываемые из changeset
    ├── 001-init-database.sql
    └── 002-collector-tables.sql
```

## Именование

| Тип файла | Конвенция | Пример |
|-----------|-----------|--------|
| **Корневой changelog** | `db.changelog-master.xml` (или `.yaml`) | Соответствует дефолту Spring Boot |
| **Включаемые changelog** | `changelog-NNN-краткое-описание.xml` | `changelog-001-init-database.xml` |
| **SQL-скрипты** | `NNN-краткое-описание.sql` | `001-init-database.sql` |

- **NNN** — порядковый номер (001, 002, …), задаёт порядок выполнения.
- Имена должны быть **предсказуемыми**, чтобы легко находить файл для новой миграции (обычно — последний по номеру).

## Рекомендации

1. **Один changeset — одна логическая миграция** (один change или одна группа связанных изменений).
2. **Корневой файл** не должен содержать changeset, только `<include>` других файлов.
3. Не раздувать один файл: при большом числе changeset добавлять новый файл с следующим номером, старые не трогать.
4. Для изменений, которые должны выполняться повторно (процедуры, справочники), можно завести подпапку `rerun/` и использовать `runOnChange` / `runAlways`.
